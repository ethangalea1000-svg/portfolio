Connexion CyberLab

Pourquoi Supabase ?
Supabase est le service qui gère l'authentification et peut ensuite stocker les données de ton compte. GitHub Pages affiche CyberLab ; Supabase gère la partie compte. Les méthodes ci-dessous doivent être activées dans ton projet Supabase avant de fonctionner.

0. Mode local — sans compte ni base de données

Tu peux utiliser CyberLab sans Supabase.
Ce mode ne crée aucun compte en ligne et aucune base de données. Ton profil est enregistré uniquement dans le navigateur avec localStorage.

Ce mode n'est pas une authentification sécurisée : il fonctionne seulement sur ce navigateur/appareil. Il ne permet pas de récupérer le profil sur un autre appareil.

0.25. Compte CyberLab avec Clerk

Une autre solution d'authentification en ligne.
Clerk gère les comptes CyberLab et les connexions Google. Ton site n'a pas besoin d'une base de données CyberLab pour cette authentification. Clerk fournit aussi ses propres interfaces de connexion et d'inscription. citeturn596649search0turn596649search1

Configure une fois la Publishable Key de ton application Clerk, puis utilise les boutons ci-dessous.

Dans Clerk : active Google et l'authentification par email/mot de passe dans les méthodes de connexion. La Publishable Key est une clé publique destinée au frontend ; ne colle jamais de clé secrète ici. citeturn596649search0turn596649search2

0.5. Compte CyberLab en ligne — sans base de données

Une vraie connexion en ligne, mais sans Firestore.
Tu peux utiliser Firebase Authentication uniquement : soit avec ton compte Google, soit en créant un compte CyberLab avec email + mot de passe. Les cartes/données de CyberLab ne sont pas enregistrées dans une base Firebase par cette option.

Il faut créer/configurer un projet Firebase une seule fois. La configuration Web ci-dessous est prévue pour être utilisée côté navigateur.

Configuration : Firebase Console → Authentication → Sign-in method → active Google et/ou Email/Password. Ajoute aussi ton domaine GitHub Pages dans les domaines autorisés. Aucun Firestore n'est nécessaire pour cette méthode. citeturn489918search6turn489918search1turn489918search4

1. Configuration Supabase

Cette étape est faite par le propriétaire du projet CyberLab. Elle ne doit normalement être faite qu'une seule fois.

⚠️ Utilise uniquement une clé publique/publishable. Ne mets jamais une clé sb_secret_… ou service_role dans le navigateur.

2. Connexion rapide

Tu peux garder l'email + mot de passe et ajouter les autres méthodes. Chaque bouton utilise le fournisseur correspondant dans Supabase.

Configure d'abord Supabase et active les fournisseurs que tu souhaites.

4. Sans mot de passe

Entre ton email, puis CyberLab demande à Supabase d'envoyer un lien de connexion. Avec un Magic Link, tu cliques sur le lien reçu et tu reviens connecté sur CyberLab.

5. Passkey

Fonction avancée : les passkeys de Supabase sont actuellement indiquées comme expérimentales. Elles nécessitent une configuration spéciale et une version récente de la bibliothèque Supabase. citeturn501658search16

Une passkey peut utiliser le mécanisme de sécurité de ton appareil ou un gestionnaire de mots de passe compatible (par exemple biométrie, code de l'appareil ou clé de sécurité). Le principe est de ne pas saisir un mot de passe partagé. citeturn501658search16

Mode d'emploi : activer les méthodes

Les boutons existent déjà sur cette page, mais Supabase doit connaître chaque fournisseur. Le principe OAuth est : CyberLab envoie l'utilisateur vers Google/GitHub/etc., le fournisseur l'authentifie, puis il redirige vers CyberLab. citeturn921001search0

Google

Dans Supabase : Authentication → Providers → Google. Puis configure ton projet Google Cloud / Google Auth Platform, récupère les identifiants OAuth et reporte-les dans Supabase. citeturn921001search3

GitHub

Crée une GitHub OAuth App, récupère son Client ID et son Client Secret, puis active GitHub dans Supabase. Supabase fournit une Callback URL du type https://TON-PROJET.supabase.co/auth/v1/callback. citeturn921001search5

Discord

Crée une application Discord dans le Developer Portal, récupère les identifiants OAuth, puis active Discord dans Authentication → Providers de Supabase. citeturn921001search10

Apple

Active Apple dans le tableau de bord Supabase et configure le fournisseur Apple selon le flux Web choisi. citeturn921001search7

Microsoft

Supabase utilise le fournisseur Azure pour Microsoft. Active Azure dans Supabase et configure le Tenant URL / les identifiants de ton application Microsoft. Le scope email est requis. citeturn921001search15

GitLab

Crée une application OAuth GitLab, récupère son Application ID et son Secret, puis active GitLab dans Supabase. citeturn921001search11

Magic Link

Le Magic Link utilise signInWithOtp() avec une adresse email. Supabase envoie ensuite le lien de connexion. La configuration du template email détermine le lien ou un code OTP. citeturn501658search0turn501658search17

Passkey

Active Passkeys dans Authentication → Passkeys, active l'option expérimentale dans le client Supabase et inscris une passkey après qu'un utilisateur est connecté. citeturn501658search16turn501658search4

6. Ma collection

Sans connexion, tes cartes restent enregistrées sur cet appareil. Une fois l'authentification et la base de données correctement configurées, la prochaine étape est de synchroniser ces cartes dans Supabase pour les retrouver sur plusieurs appareils.
